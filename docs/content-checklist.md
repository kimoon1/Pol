# 다음 콘텐츠 업데이트에 필요한 자료

이 문서는 편집용 메모이며 사이트 화면에 표시하지 않습니다. 확인되지 않은 내용을 완료된 구현이나 성과로 추가하지 않습니다.

## 반영 기준

- 기존 저장소의 이력서 기반 경력 정보와 2026-11-09 사용자 설명을 반영했습니다.
- 총 경력은 기존의 4년 표기를 유지했습니다. 정확한 입·퇴사일 확인 후 변경합니다.
- NestJS·FastAPI 경험 1–2년은 총 경력 안에서의 경험입니다.
- ERP는 프론트엔드 포함, Python·LangGraph, 사내 조직·정책 조회, 벡터 검색 미사용으로 정리했습니다. 슈퍼바이저 형태의 노드 구성, 사용자별 노드 기능 사용 시 권한 검사, 노드별 병행 조회 설계는 사용자 추가 설명으로 확인했습니다.
- 광고 생성기의 NestJS·Python·FastAPI, 외부 API 생성, 광고매체 등록, 대시보드, LLM 성과 분석은 사용자 설명을 반영했습니다. 회사명, 시작일, 기능별 완료 범위는 추정하지 않았습니다.
- 근거가 제공되지 않은 유지보수 시간 30% 단축 수치는 노출하지 않습니다.

## ERP

- 실제 데이터 조회 경로(DB/API 등)와 조직·정책 조회 분기.
- 권한 검사 툴의 구체적 처리와 데이터가 모델에 전달되기 전/후의 처리.
- LangGraph 구성과 선택 이유. 벡터 검색을 사용하지 않은 실제 이유.
- 프론트엔드 상태 관리, 로딩/실패/접근 불가 처리 중 실제 구현 내용.
- 익명화 가능한 화면, 역할별 접근 테스트, 응답 품질 확인 결과.

## 업로드 서버

### 사용자 설명으로 확인해 반영한 범위

- PHP 7.3 레거시를 PHP 8.3·DDD 기반으로 전면 리팩토링했습니다.
- 컨버터 서버는 파일 수신·Private S3 저장·검사를 담당하고, 검사 통과 작업을 업로드 서버로 전달합니다.
- 업로드 서버는 영상 Vimeo 연동, 이미지 크기별 변환·썸네일 생성을 담당하고 완료 정보를 SQS에 등록합니다.
- DB 큐를 SQS로 전환했으며 SQS 연동 코드는 본인이 담당했습니다. API 서버가 크론으로 완료 메시지를 소비해 파일 정보를 DB에 반영합니다.
- 업로드 서버의 DB 직접 접근을 제거했고, 기존 업로드 토큰 체계는 제거했습니다. 토큰 제거 자체를 보안 성과로 표현하지 않습니다.
- 서버 사양은 참고용 정보이므로 사이트·경력 요약·공개 문서에 기재하지 않습니다. 운영 환경은 서버별 역할과 Private S3·SQS·Vimeo 연동으로 설명합니다. 물리 서버 수나 active-active 방식은 추정하지 않습니다.
- 인프라·보안팀과 협업한 애플리케이션 코드 개발 사례입니다. 서버·AWS 리소스·rsync 환경 구축을 본인 기여로 표현하지 않습니다.
- S3 파일 전달 구조 개선은 별도 프로젝트로 유지합니다.
- DDD 적용 설명에는 DTO 통신 규칙, Repository·Service 코드 분리, Service에서 외부 연동 호출이라는 실제 구성만 사용합니다. 제공되지 않은 폴더·클래스·도메인 모델은 추정하지 않습니다.
- 파일 확장자 거부 → 프론트 알림, 확장자 통과 후 용량·해시 등 파일 검사 거부 → 프론트 알림, 모든 검사 통과 → 큐 등록을 사용자 확인 사례로 반영했습니다. 이를 자동화 테스트나 별도 테스트 로그로 표현하지 않습니다.

### 추가 자료가 필요한 항목

- 공개 가능한 DDD 디렉터리와 대표 코드가 제공되면 현재의 책임 구분 설명에 추가할 수 있습니다.
- 검사 항목과 실패 처리, 서버 간 요청 인증·인가 방식, 임시 파일·S3 접근 정책.
- 메시지 구조, 실제 큐 구성, 처리 실패·재시도·중복 메시지 처리와 API 크론의 DB 반영 방식.
- 검증 기록·측정값이 존재하는 경우에만 성능이나 장애 대응 성과를 추가합니다.
- 확장자 허용 목록, 용량 제한값, 해시 검사 목적·알고리즘 등 세부 검사 규칙은 아직 제공되지 않았습니다.
- 첨부 보안 검토 문서의 RCE·검사 우회 등은 가설입니다. 실제 발견·해결한 취약점으로 공개하지 않습니다.
